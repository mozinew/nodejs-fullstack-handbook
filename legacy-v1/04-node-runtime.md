# 04 Node.js 运行时、异步模型与核心 API

## 运行模型

V8 执行 JavaScript，libuv 提供事件循环、线程池和跨平台 I/O。网络 I/O 通常由操作系统异步完成；文件、DNS、部分加密任务使用线程池。JS 主线程仍会被 CPU 密集工作阻塞。

Node 适合 API/BFF、I/O 密集服务、实时协作、工具链和云函数。CPU 密集任务应使用 Worker Threads、子进程或独立计算服务。

## 项目用到的核心 API

| API | 用途 | 关注点 |
|---|---|---|
| `fs` | 加载函数、写临时 Excel | 路径穿越、同步 I/O、清理 |
| `path` | 解析工作区与函数入口 | 规范化、平台差异 |
| `http/https` | 调用 OpenAPI | 超时、连接复用、TLS |
| `Buffer` | HTTP/Excel 二进制 | 编码、大小、内存 |
| `process.env` | 本地配置 | 全是字符串、缺省校验、保密 |
| `URL` | 解析地址 | 协议校验、SSRF |
| `require.cache` | 本地热加载 | 模块单例与缓存失效 |

## Stream 与背压

Buffer 是内存字节，Stream 分段传输。`apaas-openapi.cjs` 聚合响应 chunk，适合有限大小 JSON。aPaaS `findStream` 是数据层流式分页，但若每批都 push 到总数组，最终仍占全量内存；真正流式处理应在批内转换、写出或更新。

## 超时、取消、重试

外部调用应定义连接/响应超时、AbortSignal、可重试错误、指数退避加抖动、次数上限和幂等键。只重试超时、限流和部分 5xx，不重试参数或权限错误。

## 批处理设计清单

- 单批大小由记录限制、包大小、QPS 和超时共同决定。
- 并行度必须显式受控。
- 部分失败记录业务键、批次号和原因，支持重放。
- “创建前查重”不能阻止并发重复；需唯一约束或幂等记录。
- 长任务要有进度、断点和摘要。

云函数会冷启动、复用和扩缩实例，不能依赖进程内变量永久存在；文件系统通常临时，文件上传后应清理。
